# Hana视频读取 0.1.2

Hana 原生 v2 工具 App。复用 SAOS-3624/dsh-video-storyboard 0.4.3 与本工作室 action.3 实验内核，用本地视频生成真实 PNG、帧时间和有预算的补看证据。

**它不自动理解动作、不计算准确率，也不把“生成了图”当成“模型看懂了”。** 当前定位是实验版；声音增强、人工核验及效果提升尚未达标。

## 在对话中使用

安装并授权工具给当前助手后，可说：“用视频读取看这段视频0到10秒，先描述动作，再指出哪里需要补看。”

工具 `video_evidence`：
- `health`：检查当前FFmpeg/FFprobe；不自动安装。
- `configure`：通过正式App设置接口保存两个现有可执行文件路径。也可从应用设置页填写。
- `start`：传 `fileId` 或本地绝对 `input`（二选一）及 `from/to`，0<=from<to，窗口<=12秒；返回概览PNG与reviewId。
- `inspect`：沿用reviewId，窗口须在原窗口内；sequence为动作前后9格，detail为3格较大画面，**不是区域裁剪**。
- `status` / `finish`：查询和结束；只返回文本，不重复喂图。
- `export`：把当前review的证据JSON通过宿主作为附件交付。PNG和源视频快照保存在App自有数据目录，不随源码包分发。

每份review最多3张图、5次生成尝试；重复同一补看请求只返回既有文本/证据，不追加图片。复核ID只允许原会话访问，重启后不恢复活跃预算。不得为绕过预算连续开新review。输入最多512MiB；当前会复制一份源视频到自有数据目录，可在人工检查后清理；本App不自动删除用户源文件。

## 证据与限制

0.1.1 修复概览和普通补看把请求时间误作实际帧时间的问题：记录解码帧 PTS 与独立的请求时刻；不能获取可信时间时明确报错。0.1.2 只修正 health 与 evidence 中 appVersion 仍显示 0.1.0 的元数据错误，功能与 0.1.1 相同。此修复不代表动作识别准确率提升。

- 微网格记录每张子图的真实解码PTS、请求时刻、行列号；父格不捏造单一时刻。
- 精确匹配概览微网格区间时，sequence补看改取槽起点；普通sequence仍取中点。并不保证解码帧一定不同或捕捉到单帧闪现。
- 输出原始PNG图片内容块，不能只交文件路径就声称模型已看图。
- 音轨分析/ASR固定关闭，不调用云端、不联网下载、不扫描硬盘、不读其他App配置或模型凭据。
- token用量未知。移除了上游文本清单中的固定384估计，不把像素数当token实测。
- 原始帧之间的连续轨迹、声音、心理活动与跨镜因果，证据不足就标未知。
- 对照必须固定源视频哈希、窗口、模型路由、提问与图像预算；追加补看成本另列。此版本仅提供action.3行为，尚无插件内旧版切换。准确度可先对锁定参考探索性评分，不能据此宣称较旧版提升。

## 权限说明

只申请三个能力：工具暴露、读取明确传入的资源、运行外部FFmpeg进程。文件先经宿主ResourceIO授权导入，所有输出与缓存留在本App自有目录。工具路径通过公开 `sdk.process.resolveExecutable` 解析，不扫描系统目录。

`app/process.spawn` 是较强权限：外部FFmpeg并不自动继承AppHost的细粒度读写/联网限制。本App不发起网络输入，拒绝URL/UNC和播放列表；这不是对恶意媒体的安全沙箱保证。仅处理用户信任的本地视频。

不包含FFmpeg二进制、Python、模型权重、测试视频、凭据或用户数据；依赖用户已有FFmpeg/FFprobe。无需DSHana运行时，也不修改现用DSH插件。
